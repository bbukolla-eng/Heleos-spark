# HELIOS Takeoff Core P0 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a local-first, evidence-bound P0 foundation that preserves document revisions, takeoff decisions, pricing provenance, and bid-release approvals.

**Architecture:** A standard-library Python package uses SQLite as its local canonical store. SQL migrations establish append-only resource tables and integrity triggers; a service layer performs controlled lifecycle operations; a WSGI JSON API and OpenAPI document provide the future app boundary.

**Tech Stack:** Python 3.12, sqlite3, decimal, uuid, unittest, wsgiref; no third-party runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-08-27-p0-foundation-design.md`

**Execution status (2026-08-27):** Tasks 1–6 are implemented on `feat/p0-foundation`. The completed build has eight immutable migrations, loopback API/CLI/package support, the agentic-layer boundary, a runnable demo, and the acceptance record at `docs/verification/p0-acceptance.md`. The unchecked boxes below are preserved as the original execution prompts, not a statement that the task remains unfinished.

## Global Constraints

- Python 3.12 standard library only at runtime; tests use `unittest`.
- Persist quantity and price values as canonical decimal strings, never floats.
- Every resource ID is a UUID string generated by the service layer.
- Use `PRAGMA foreign_keys = ON` for every SQLite connection.
- Never update or delete source/evidence/claim/quantity/takeoff/quote/estimate/release data; create replacement or decision rows instead.
- A frozen revision set is immutable; an approved snapshot remains immutable when documents change.
- Public API must not expose raw SQL or database implementation details.
- Every migration file is immutable once committed. Follow-up schema changes use the next numbered migration.
- A review/approval/release checks a stored, project-scoped role grant; callers never select their own role.
- Retriable API mutations use an idempotency key and request fingerprint.
